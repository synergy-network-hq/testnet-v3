Section 1

Introduction & SynQ Ecosystem

⚙️

Post-Quantum Smart Contracts

Aegis PQSynQ is the cryptographic backbone of the SynQ smart contract VM.

Aegis PQSynQ is a specialized post-quantum cryptography facade crate designed for the SynQ VM and compiler ecosystem. SynQ is Synergy Engineering Labs' own smart contract virtual machine and domain-specific language, analogous to EVM for Ethereum or Move for Aptos. PQSynQ provides all NIST-standardized post-quantum algorithm families through a clean, trait-based API that SynQ programs use for transaction signing, smart contract attestation, quantum-safe channel establishment, and verifiable randomness.

Key Features

  • ML-KEM-512/768/1024 (key encapsulation)
  • ML-DSA-44/65/87 (digital signatures)
  • HQC-KEM-128/192/256 (alternative KEM)
  • FN-DSA-512/1024 (alternative signature)
  • Contextual signing with domain separation
  • wasm32 compatible (--no-default-features)
  • Zero-copy trait-based abstractions

Canonical Import

// In your SynQ Cargo.toml

ℹ️
SynQ Context SynQ programs use aegis-pqsynq to sign transactions (ensuring only the correct sender can execute), verify smart contract state transitions (preventing double-spending or invalid state changes), establish quantum-safe channels between VM participants, and generate verifiable randomness for protocol operations. All cryptographic operations are deterministic and auditable.
Section 2

Architecture & Facade Pattern

🏗️

Trait-Based Abstraction

Clean API hides algorithm complexity; swap implementations without breaking contracts.

Two Core Traits

PQSynQ exposes two main traits: KeyEncapsulation (KEM) and DigitalSignature. All algorithms implement these traits:

pub trait KeyEncapsulation {
    fn keygen(&mut self) -> Result<(Vec, Vec)>;
    fn encapsulate(&mut self, pk: &[u8]) -> Result<(Vec, Vec)>;
    fn decapsulate(&mut self, ct: &[u8], sk: &[u8]) -> Result>;
}

pub trait DigitalSignature {
    fn keygen(&mut self) -> Result<(Vec, Vec)>;
    fn detached_sign(&mut self, msg: &[u8], sk: &[u8]) -> Result>;
    fn verify_detached(&mut self, msg: &[u8], sig: &[u8], pk: &[u8]) -> Result;
    fn sign_ctx(&mut self, msg: &[u8], sk: &[u8], ctx: &[u8]) -> Result>;
    fn verify_ctx(&mut self, msg: &[u8], sig: &[u8], pk: &[u8], ctx: &[u8]) -> Result;
}

Algorithm Factories

Create algorithm instances via factory functions:

let kem = Kem::mlkem512();       // ML-KEM-512
let kem = Kem::mlkem768();       // ML-KEM-768
let kem = Kem::hqckem128();      // HQC-KEM-128

let sig = Sign::mldsa44();        // ML-DSA-44
let sig = Sign::mldsa65();        // ML-DSA-65
let sig = Sign::fndsa512();       // FN-DSA-512
🎯

Trait Abstraction

Algorithms implement standard traits; contracts don't care about implementation details.

🔄

Pluggable Implementations

Swap algorithms by selecting different factory; no contract code changes.

⚡

Zero-Copy API

Operates on byte slices; minimal allocation overhead.

Add PQSynQ to Your SynQ Project

  2. 2

  3. 3

  4. 4
    Perform Cryptographic Operations Call keygen, sign, verify, encapsulate, decapsulate via trait methods.

Minimal SynQ Contract Example

use pqsynq::{Kem, Sign};

pub contract QuantumSafeVault {
    fn setup(&mut self) {
        // Generate signature keypair for contract owner
        let mut signer = Sign::mldsa44();
        let (vk, sk) = signer.keygen().unwrap();
        
        // Store public key for later verification
        self.owner_pubkey = vk;
    }
    
    pub fn withdraw(
        &mut self,
        amount: u64,
        signature: &[u8],
        owner_sk: &[u8],
    ) -> Result {
        // Verify withdrawal is signed by owner
        let mut signer = Sign::mldsa44();
        let msg = format!("withdraw:{}", amount).as_bytes().to_vec();
        
        let is_valid = signer.verify_detached(
            &msg,
            signature,
            &self.owner_pubkey
        )?;
        
        if !is_valid {
            return Err("Invalid signature");
        }
        
        // Process withdrawal
        self.balance -= amount;
        Ok(())
    }
}
Section 5

KEM & Signature API Reference

📚

Complete Function Reference

All public API functions documented with examples.

Key Encapsulation (KEM) Example

use pqsynq::{Kem, KeyEncapsulation};

fn kem_roundtrip() -> Result<()> {
    let mut kem = Kem::mlkem512();
    
    // Receiver: generate keypair
    let (pk, sk) = kem.keygen()?;
    
    // Sender: encapsulate to receiver's public key
    let (ciphertext, shared_secret_sender) = kem.encapsulate(&pk)?;
    
    // Receiver: decapsulate ciphertext to recover shared secret
    let shared_secret_receiver = kem.decapsulate(&ciphertext, &sk)?;
    
    // Verify both sides recovered same secret
    assert_eq!(shared_secret_sender, shared_secret_receiver);
    
    Ok(())
}

Digital Signature Example

use pqsynq::{Sign, DigitalSignature};

fn signature_roundtrip() -> Result<()> {
    let mut signer = Sign::mldsa44();
    
    // Signer: generate keypair
    let (vk, sk) = signer.keygen()?;
    
    // Signer: detached sign a message
    let message = b"Important transaction";
    let signature = signer.detached_sign(message, &sk)?;
    
    // Verifier: verify signature
    let is_valid = signer.verify_detached(message, &signature, &vk)?;
    assert!(is_valid);
    
    Ok(())
}

Section 7

Domain Separation & Contextual Signing

🔒

Prevent Signature Reuse Across Contexts

Domain separation ensures signatures are bound to specific SynQ contract types.

Contextual Signature API

ML-DSA supports sign_ctx(msg, sk, context) and verify_ctx(msg, sig, pk, context). This prevents signature replay attacks across different contract types.

use pqsynq::{Sign, DigitalSignature};

// Contract A: Payment transfer
let mut signer = Sign::mldsa44();
let msg = b"transfer:100";
let ctx = b"synq-contract-payment-v1";  // Domain separation
let sig_a = signer.sign_ctx(msg, &sk, ctx)?;

// Contract B: Voting (different context)
let ctx_b = b"synq-contract-voting-v1";  // Different domain
let sig_b = signer.sign_ctx(msg, &sk, ctx_b)?;

// sig_a cannot be used in voting context (and vice versa)
let valid = signer.verify_ctx(msg, &sig_a, &vk, ctx_b)?;  // Returns false

FN-DSA Note

FN-DSA does not support contextual signing. If you use FN-DSA, you must implement domain separation manually by prepending context to the message:

let mut signer = Sign::fndsa512();
let ctx = b"synq-contract-type-v1";
let msg_with_ctx = [ctx.as_slice(), msg].concat();
let sig = signer.detached_sign(&msg_with_ctx, &sk)?;
✓
Domain Separation Best Practice Always use context-aware signatures (sign_ctx/verify_ctx) when available. If using FN-DSA, prepend a context identifier to all messages. This prevents signature reuse across different SynQ contract types.

SynQ Smart Contract Patterns

⚡

Common PQC Usage Patterns

Real-world smart contract examples using aegis-pqsynq.

Pattern 1: Transaction Signature Verification

pub contract PQWallet {
    pub fn execute_transaction(
        &mut self,
        recipient: Address,
        amount: u64,
        signature: &[u8],
    ) -> Result<()> {
        // Only owner can execute (verified via ML-DSA signature)
        let mut signer = Sign::mldsa44();
        let tx_msg = format!("tx:{}:{}", recipient, amount);
        
        let is_valid = signer.sign_ctx(
            tx_msg.as_bytes(),
            &signature,
            &self.owner_pubkey,
            b"synq-wallet-transaction-v1"
        )?;
        
        if !is_valid {
            return Err("Signature invalid");
        }
        
        self.balance -= amount;
        emit_transfer(recipient, amount);
        Ok(())
    }
}

Pattern 2: Quantum-Safe Session Establishment

pub contract PQChannel {
    pub fn initiate_handshake(
        &mut self,
        peer_ml_kem_pk: &[u8],
        peer_signature_pk: &[u8],
    ) -> Result> {
        // Establish quantum-safe session via ML-KEM key exchange
        let mut kem = Kem::mlkem512();
        let (ciphertext, session_secret) = kem.encapsulate(peer_ml_kem_pk)?;
        
        // Sign ciphertext to prove ownership of this contract
        let mut signer = Sign::mldsa44();
        let sig = signer.sign_ctx(
            &ciphertext,
            &self.my_signature_sk,
            b"synq-channel-handshake-v1"
        )?;
        
        // Store session secret for future encrypted communication
        self.session_key = kdf_session(&session_secret)?;
        
        Ok([ciphertext, sig].concat())
    }
}

Pattern 3: Attestation & Proof

pub contract PQAttestor {
    pub fn issue_attestation(
        &mut self,
        claim: &[u8],
    ) -> Result> {
        // Attestor signs claim with ML-DSA-44
        let mut signer = Sign::mldsa44();
        let attestation = signer.sign_ctx(
            claim,
            &self.attestor_sk,
            b"synq-attestation-v1"
        )?;
        
        Ok(attestation)
    }
    
    pub fn verify_attestation(
        &mut self,
        claim: &[u8],
        attestation: &[u8],
        attestor_pk: &[u8],
    ) -> Result {
        let mut signer = Sign::mldsa44();
        signer.verify_ctx(
            claim,
            attestation,
            attestor_pk,
            b"synq-attestation-v1"
        )
    }
}
