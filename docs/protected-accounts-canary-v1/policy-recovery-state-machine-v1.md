# Native policy and recovery candidate

One pending transition per registered account. Both schedule actions require finalized current policy, current ledger nonce, and existing account/Genesis coordinate. Decode the full policy using APQE's standalone policy decoder, require exact old and new canonical hashes, the same aggregate point/profile/Genesis/account/delays, current epoch + 1, only the designated D or P changes, and strictly greater role key version with fresh participant/key and independent PoP. No R replacement in v1. Reason 1 means device change for ordinary or lost device for recovery; all other reasons are unsupported. Both schedule forms sign activation_at and the full policy. Native replacements independent from EVM share changes are permitted only as such; cross-domain recovery needs provider-authenticated continuity (recovery payload key 7), explicit separate status and a genuine custody drill. Equality of points alone is not proof of share refresh.

| Operation | Required current proof | State and clock condition | Atomic outcome |
|---|---|---|---|
| Policy schedule (28676) | D+P and replacement PoP | No pending; activation_at ≥ inclusion consensus time + 7200 | Commit pending transition, advance nonce once, charge signer. Active policy unchanged. |
| Policy cancel (28677) | D+P | Exact pending policy-change reference; inclusion time < activation_at | Clear transition, advance nonce, fee; do not change policy. |
| Policy activate (28678) | Deterministic consensus scheduler, no submission | Schedule finalized, time ≥ activation_at; current policy precondition | Install exact new policy and increment epoch. Preserve current ledger nonce. No fee or second user nonce. |
| Recovery schedule (28679) | R and current survivor, and replacement PoP | No pending; activation_at ≥ inclusion consensus time + 172800; authenticated scope/continuity | Commit pending transition and charge/advance once. |
| Recovery veto (28680) | Current role being replaced alone, scoped to exact reference | Exact recovery reference, inclusion time < activation_at | Terminal veto of this reference; clear pending, charge/advance once; no authority swap. |
| Recovery cancel (28681) | D+P | Exact recovery reference, inclusion time < activation_at | Clear pending, charge/advance once; no authority swap. |
| Recovery activate (28682) | Deterministic consensus scheduler, no submission | Schedule finalized, time ≥ activation_at; all state/continuity checks | Atomically swap policy, epoch++, preserve nonce; no fee or second user nonce. |

Checked integer arithmetic only. Pending ID = SHA3-256(ASCII("AEGIS/PROTECTED-PENDING/v1") || original canonical scheduling native intent). Scope activation to the exact pending ID and expected old policy bytes. Store the full new policy, actor-role mode, activation_at, created height and verified continuity reference. Propose ordering before fee-bearing actions at the first eligible proposal that observes finalized schedule; sort due operations by (activation_at, account ID). A hard per-block dispatch bound and starvation proof must be measured and ratified before enabling scheduler. Empty blocks can drive activation. Cancellation/veto below the deadline are ordered by ordinary ledger nonce and block order; first committed terminal operation wins; at equality only activation is eligible. If a valid cancel/veto is in an earlier canonical ancestor at activation, its effect wins; never use wall clock, delivery of notification, or local mempool time. No off-chain operator can cancel. Old D/P can spend while pending subject to the existing restrictions. Epoch never resets; stale old keys and signatures cannot execute after activation. Emit terminal results via canonical receipt/event journal, retaining no redundant tombstone after finality beyond existing nonce/replay and receipt state. Restart/rejoin restores verified active and pending state without reenacting an activation.

This table proposes consensus semantics; the Core branch does not yet implement or qualify these seven transitions. Before ratification, implement the isolated scheduler and test equality, cancellation-veto ordering, lost-D/lost-P, fee-on-revert, old epoch and crash/rejoin, and review APQE's pure contextual single-role veto adapter.
